## Findings considered and rejected

- **A `minimal` third detail tier**: two modes (standard/full) cover the
  identified needs; a third tier adds contract surface with no concrete use
  case yet.
- **Making truncated attachments ID-addressable via a new fetch tool**:
  attachments (link unfurls, bot payloads) have no stable Slack-side ID to
  fetch by; `attachment_get_data` handles *files* only. Re-fetch with
  `detail: full` is the honest lossless path.
- **Per-row Permalink column in compact mode**: ~100 chars/row of derivable
  data; the `#link_template:` legend line (plan 003) recovers the capability
  at one line per response. Note history/replies never had permalinks even in
  full mode (`convertMessagesFromHistory` doesn't populate the field).
- **`#channels:` legend line**: deferred until there's evidence agents need
  channel-name resolution beyond what the Channel column already carries
  (search rows embed `ID (#name)`).
